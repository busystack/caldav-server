# Security verification checklist

This is an application-specific applicability and evidence checklist against [OWASP ASVS 5.0.0](https://asvs.owasp.org/), checked against the [versioned official requirements](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.csv) on 2026-10-27. Requirement identifiers below use that exact version. It is not a complete per-requirement assessment, an ASVS level claim or external certification. “Focused evidence” means the named checks passed in the recorded runs; it does not pass an entire ASVS chapter. Final release qualification remains in [conformance](conformance.md) and [executed evidence](../qualification/evidence/README.md).

| ASVS 5.0.0 reference | Application scope and current evidence | Assessment or remaining work |
| --- | --- | --- |
| 1.2.4 | Production JDBC queries use bound parameters for account, resource, membership and credential values. Store/workflow tests exercise cross-account authorization and rollback. | Source/focused evidence; independent query/injection review remains. |
| 1.5.1 | DAV XML is untrusted protocol input. iCalendar parsing is a separate parser boundary; URL-bearing data must not trigger retrieval. `CalendarContentTest` checks a custom VTIMEZONE/TZURL against a local non-fetch sentinel. | Full DAV XML/DTD/entity/nesting/streamed-body qualification remains necessary. iCalendar tests do not establish XML safety. |
| 3.3.1–3.3.4 | Session cookies are Secure, HttpOnly and SameSite=Lax; cross-site OIDC needs a safe top-level callback. Session values remain out of pages. | Partial: current `JSESSIONID` name lacks the ASVS cookie prefix. A `__Host-` cookie also conflicts with non-root cookie paths; a documented secure-prefix decision is required. Distinct-site browser callback qualification is recorded separately. |
| 3.5.1 | Browser mutations keep Spring CSRF protection. DAV uses a separate non-cookie chain with a strict browser Origin boundary; consent and explicit identity linking are protected browser operations. `SecurityBoundaryIT` and workflow tests exercise these boundaries. | Focused evidence; complete browser cross-origin matrix and independent review remain. |
| 6.2.1–6.2.12 | Local passwords use a 14-character minimum, no composition rule, exact verification and a 72-byte UTF-8 maximum; forms support password managers. Users change passwords after recent MFA and current-password verification. | Partial: no common/breached-password blocklist or contextual-word list; 72-byte BCrypt input limit cannot accept 64 arbitrary Unicode characters. Do not claim all password requirements. |
| 6.3.3, 6.4.3–6.4.4 | Sensitive account/client/collection changes require recent primary and actual WebAuthn factors. Initial factor enrollment requires primary authentication; operator recovery is local, identity-verified and clears old access. | `PasskeyPersistenceIT`, workflow tests and interim CTAP2 browser evidence; physical devices and operational identity-proofing review remain. |
| 6.5.1–6.5.6 | Recovery codes are generated from secure randomness, stored as high-entropy verifiers, expire and are consumed transactionally; concurrent use has one winner. Factor removal/recovery revokes client access. | Focused `AccountSecurityWorkflowsIT` evidence; final browser recovery and operator procedures need combined qualification. No TOTP or push mechanism is advertised. |
| 7.2.1–7.2.4, 7.4.1–7.4.3 | Spring Session JDBC stores sessions; authentication rotates the identifier. Account generation checks prevent delayed logins/requests reviving reset access. Logout, disable, password change and recovery invalidate durable sessions. | Nineteen focused HTTPS/PostgreSQL workflow tests and V7 real browser same-cookie/session/passkey restart/disable profiles passed; final integrated artifact remains. |
| 7.3.1–7.3.2 | Browser inactivity expires after 30 minutes; sensitive factors must be within ten minutes. Upstream identity verification has a configurable maximum of 24 hours. | Partial: a distinct absolute browser-session lifetime is not implemented. Recent-factor checks and upstream bounds do not substitute for that requirement. |
| 8.2.1–8.2.3 | Stable principal UUIDs, ownership and READ/WRITE memberships are checked in services/storage; application administration does not imply calendar ownership. | Store sharing/revocation tests and nonadministrator OIDC tests; all DAV discovery/query/multiget/freebusy/sync leakage paths still require complete qualification. |
| 10.1.2, 10.2.1 | Spring OIDC client uses session-bound state/nonce/PKCE; explicit identity linking binds recent MFA intent to the matching callback state. Trusted issuer and subject determine identity; email and upstream roles do not grant ownership/admin. | Five real HTTPS Keycloak and four identity persistence tests passed; V7 distinct-site Chromium organization+passkey callback/restart/disable profile passed. |
| 10.4.1–10.4.6, 10.4.8–10.4.9 | Embedded Spring issuer permits approved public native code+S256 clients. JDBC grants and opaque reference tokens have durable rotating refresh families, replay revocation, absolute expiry and account-state enforcement. Users revoke grants in the browser. | V7 focused OAuth 14 and ledger 9 tests passed, including replay/concurrency/removal boundaries. V7 real browser S256 consent/code/refresh/grant-revocation passed; final integrated artifact remains. |
| 10.4.7, 10.4.10, 10.4.13–10.4.16 | Open dynamic registration, confidential downstream clients, PAR, sender-constrained tokens and authorization-details are outside the selected public-native opaque bearer profile. | These mechanisms are not advertised. ASVS L3 requirements are not claimed; optional upstream OIDC is a separate confidential-client role. |
| 11.4.2 | Spring BCrypt cost 12 verifies human passwords and upgrades lower costs through its supported hook. DAV verifiers use adaptive hashing; random OAuth/recovery values use framework generators/secure randomness and purpose-specific persisted state. | Focused lifecycle tests; independent cryptographic/configuration review and workload tuning remain. No custom authentication cryptography is implemented. |
| 12.2.2, 12.3.2–12.3.4 | Validated HTTPS public base/issuer; deployment terminates TLS at a restricted proxy or embedded TLS. Tests use a disposable CA with normal hostname and chain validation; provider trust is scoped to that fixture. | Focused embedded HTTPS, V7 Nginx `/team` browser and real cross-site provider profiles passed; final integrated artifact and operator certificate lifecycle remain. No trust-all production switch exists. |
| 13.2.1, 13.3.1–13.3.4 | Compose mounts secrets from a host-private directory; application PostgreSQL role is a separate non-superuser. Bootstrap/recovery password files are owner-only. Images/repository contain no generated credentials. | Partial: static database password and file-backed secret lifecycle differ from the stronger ASVS backend-credential/secret-service model. Rotation and host access remain operator responsibilities. |
| 13.4.1–13.4.5 | Runtime image excludes source-control metadata/test code. Exact DAV firewall allowlist excludes TRACE/locking; only local health is exposed and the documented proxy blocks management paths. | Source/embedded-boundary evidence; final container/proxy qualification remains. |
| 15.1.2, 15.2.1–15.2.4 | Pinned build/plugins/images, dependency management and runtime CycloneDX inventory; required OSV gate has pagination/feed-failure tests and a vulnerable positive control. | See [dependency/advisory evidence](../qualification/security/README.md); container OS advisory/notice review and ongoing remediation policy remain. Scan results are dated observations. |
| 15.2.2 | Resource/form/body, parser-callback, database-pool, ceremony and throttle bounds exist. Query/recurrence work must fail explicitly when its budget is exceeded. | Full hostile XML/calendar/query matrix and representative workload measurements remain; container memory limits alone do not prove availability. |
| 16.2.5, 16.3.1–16.3.4, 16.4.1–16.4.3 | Durable bounded account security audit records actions/outcomes and hashed peers. HTTP fixture logs omit query strings, authorization values and contents. Errors suppress stack traces and parser payloads. | Partial: complete layer log inventory, coverage review, tamper-resistant off-host handling and operator retention policy are not qualified. No remote telemetry is required. |
| 16.5.1–16.5.3 | Explicit transaction rollback, protocol error mapping and local account disable; upstream outage does not invent a local-password fallback. Advisory/feed failures are visible failures. | Focused storage/workflow/Keycloak evidence; complete protocol failure matrix remains. |
| V5, V9, V17 | Calendar uploads are bounded iCalendar objects, with ATTACH data retained without retrieval. No general file service or WebRTC exists. CalDAV uses opaque tokens; upstream signed OIDC tokens are verified by Spring. | Applicable calendar upload/response and OIDC-token controls remain in scope; unrelated general file-service/WebRTC features are absent. |

The most consequential unfinished gates are complete DAV semantics/access-path testing, independent calendar/task clients, final packaged HTTPS/proxy/browser/restore qualification, resource measurements, distribution licensing and independent review. An operator must not infer production equivalence to another server from the presence of Spring Security or this checklist.
