# Security verification checklist

This is an application-specific applicability and evidence checklist against [OWASP ASVS 5.0.0](https://asvs.owasp.org/), checked against the [versioned official requirements](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.csv) on 2026-10-27. Requirement identifiers below use that exact version. It is not a complete per-requirement assessment, an ASVS level claim or external certification. “Focused evidence” means the named checks passed in the identified recorded runs; it does not pass an entire ASVS chapter. Results from `495989d` remain historical evidence. New correction regressions and final-artifact checks are qualified only when the current evidence index records their execution. Current qualification results remain in [conformance](conformance.md) and [executed evidence](../qualification/evidence/README.md).

Project and applicable third-party license/notice delivery, normalized Spring Session conclusions and exact artifact provenance are tracked in [the distribution inventory](third-party-licenses.md); historical evidence that predates the owner's license decision is retained unchanged.

Default DAV synchronization accepts the narrowly bounded `Depth: 1` accommodation only with XML `sync-level=1`; ordinary omitted/zero depth remains supported and explicit `false` enables strict mode. This deliberate RFC 6578 header exception changes neither collection scope nor authorization. Continuations are scoped to actor, collection generation, recovery epoch and retained history, and every page checks current access. Immutable version snapshots and a fixed high watermark prevent a page token advancing beyond changes absent from the response. Restore clears continuation state with the existing account/credential invalidation policy.

The recorded `495989d` qualification includes genuine Thunderbird 157.0.1/native-provider and python-caldav 3.6.0 cross-client calendar/task round trips and packaged HTTPS/proxy/local/federated recovery. The correction pass must rerun those clients without an enabling depth override and requalify the artifact/security/recovery entry points; current execution status belongs to the linked evidence index. Manual graphical setup, physical authenticators and additional platforms are reported according to execution. Independent review remains useful but is not an added certification prerequisite. An operator must not infer equivalence to another server from this checklist or the presence of Spring Security.
