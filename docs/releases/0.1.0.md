# BusyStack CalDAV Server 0.1.0

Release preparation is in progress. Publication and final squash-commit
qualification are pending. Do not interpret branch verification as a published
release. The final [release manifest](https://github.com/busystack/caldav-server/releases/download/v0.1.0/release-manifest.json)
will identify the exact qualified source, artifacts, checksums, Linux AMD64 image
digest and verification evidence.

This release preserves the application's CalDAV behavior, dependencies, V1–V13
database migrations and compatibility settings. The changes make Maven's project
version authoritative throughout packaging and publication and bind every
release payload to the qualified source, including deployment files and notices.

Installation uses `caldav-server-0.1.0-deploy.tar.gz`, `SHA256SUMS` and
`release-manifest.json` from the approved release. Its Compose deployment pulls
`ghcr.io/busystack/caldav-server:0.1.0` by immutable registry digest on Linux AMD64,
without source, Maven or host Java. The JAR alternative is
`caldav-server-0.1.0.jar`, requiring Java 25 and PostgreSQL 18.6.
Follow the generated `INSTALL.md` and [operations guide](../operations.md).
Operators supply their own domain, trusted HTTPS termination and private secrets.

The default synchronization Depth 1 accommodation and narrow local-observance
UNTIL repair retain their documented behavior and disable flags. There are no new
compatibility exceptions. Client support remains limited to actual versioned
qualification; the new [client record](../../qualification/evidence/releases/0.1.0/verification.json)
must pass against this executable before staging. Historical v0.0.1 results are
not v0.1.0 qualification.

The account UI is not a calendar editor. Scheduling/invitation or notification
delivery, alarm execution, CardDAV, automatic failover and unqualified platforms
remain outside the supported profile. See [calendar semantics](../calendar-semantics.md),
[OIDC operations](../keycloak.md), [compatibility](../observance-until-compatibility.md)
and [license inventory](../third-party-licenses.md). The project is Apache-2.0;
retain separately licensed third-party notices and the runtime SBOM.
