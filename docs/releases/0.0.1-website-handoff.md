## Installation content

Primary path: downloadable `caldav-server-0.0.1-deploy.tar.gz` from the release;
verify `SHA256SUMS`, extract, edit `.env` using the safe example, create separate
file-backed secrets and run the bundled Compose configuration. It pulls the
published application by **version and immutable registry digest**, without source,
Maven or host Java. Use the manifest for the current digest and checksums.

Alternative: release asset `caldav-server-0.0.1.jar`, requiring Java 25 (qualified
Temurin 25.0.4.1+1) and PostgreSQL 18.6. Do not advertise DEB/RPM/APT/Snap, ARM64,
Windows containers or other unqualified deployment environments.

Required administrator content, based on the release's included `INSTALL.md` and
[operations guide](https://github.com/busystack/caldav-server/blob/v0.0.1/docs/operations.md):

- Linux AMD64, Docker Engine/Compose v2 (2.24.4+), private persistent DB/storage,
  and separate backup storage. Explain container and JAR prerequisites separately.
- Operator supplies actual domain/DNS, reverse proxy, trusted HTTPS certificate,
  private key and renewal. Downloads do not supply domain/certificate. Show links
  to complete supplied root/subpath Nginx examples; preserve configured subpath,
  deny public actuator access, retain loopback application and private DB.
- No default administrator credentials. Use the local file-based bootstrap,
  then first browser login, passkey enrollment and MFA, ordinary user provisioning,
  event/task collections and per-client named DAV secret. Preserve owner-only
  bootstrap and private database-secret directory permissions.
- Use account page's displayed HTTPS CalDAV endpoint/username. Named DAV secret
  is the client password; account password is not DAV authentication. Registered
  OAuth onboarding is a separate documented option.
- Updates require verified target assets/digests, backup and migration review.
  Image rollback does not undo DB migrations. Do not invent older public releases.
- Include backup, new empty target restoration, credential invalidation and
  controlled recovery, restart persistence and removal/storage retention choices.
- Link license, third-party notices, release notes, conformance and evidence.

Use version-scoped client evidence from the release manifest's source and its
`qualification/evidence/releases/0.0.1/official-dependencies/verification.json`.
Thunderbird system/explicit America/Vancouver and explicit Europe/Berlin, and
GNOME Calendar/EDS Vancouver are required release qualification profiles; publish
