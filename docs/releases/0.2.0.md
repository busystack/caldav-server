# 0.2.0 development

This branch adds a server-rendered account and administration portal: collection
metadata/lifecycle, per-collection direct/group/effective access, connections,
security organization, contextual setup, bounded account/group/audit screens,
operational diagnostics and confirmed iCalendar portability. It retains the
existing Java/Spring/Thymeleaf/PostgreSQL stack. Published migrations V1–V14 remain
unchanged; V15 adds protected installation state.

Start with the illustrated [Getting Started guide](../GETTING_STARTED.md),
[portal guide](../portal.md), [administration guide](../administration.md)
and [portability limits and representation](../portability.md). The optional
Keycloak identity, recent-factor, recovery, OAuth, credential and CalDAV policies
remain unchanged. Proxy import limits need the documented dedicated location.

This document describes development functionality, not release qualification or
readiness. Exact source/artifact, executed browser/client/security/recovery results
and unverified environments must be recorded independently before publication.
Historical 0.1.0 client results do not qualify a different executable.

The corrective pass adds bounded disk-indexed 64 MiB / 10,000-series import,
transaction-aware confirmation retry, private crash cleanup, a shared temporary
storage ledger, metadata-only group rename, editable accessible field errors and
opaque administrative audit targets (V14). It also selects official Temurin
25.0.5+8 security maintenance binaries without modifying third-party software.
Exact executed results and outstanding release gates remain separate evidence.

New installations open the protected setup form directly. The operator obtains
the fifteen-minute code with `bash scripts/initialize.sh`. First sign-in creates
and verifies a passkey, then opens Overview or the saved task. Returning users
verify an existing passkey. Ordinary navigation continues between sensitive-action
verification windows, subject to the thirty-minute idle and eight-hour overall
browser session limits. Application-password results include the chosen app's
connection instructions, with PostgreSQL receipts preventing duplicate issuance.

V15 is forward-only. Restoring an initialized database clears outstanding setup
codes without reopening setup. Follow the updated backup/recovery instructions;
an image downgrade does not reverse database migrations.

V16 corrects a reproduced cached-plan failure in group membership reconciliation.
A function-local PostgreSQL planning preference avoids repeated nested-loop scans
after bulk growth. Permissions, atomicity and the thirty-second deadline remain
unchanged; the caller's planner settings are restored automatically. V1–V15 stay
unchanged, including earlier local V15 installation archives.

V17 admits journals as a third CalDAV resource type. V18 adds durable issuance
receipts and a recovery-code generation marker. Restore accepts complete histories
through V18 and clears retained issuance state along with other restored access.
