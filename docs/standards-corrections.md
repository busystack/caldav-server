# Independent audit correction submission

This is the developer's correction and verification submission for independent re-verification. It is not independent auditor approval, certification or a claim of universal interoperability.

The independent audit examined `release/v0.0.1` at `923ecacc6b35a77be15b6cdcde5e1b5f2b9f76f0` and reported 17 finding groups: one High, eleven Medium and five Low. It did not demonstrate account takeover, protected-calendar-content disclosure or permanent alteration of stored authoritative bytes. The fresh developer baseline reproduced all 17 groups, including 96 recorded DAV/calendar requests and separate signed WebAuthn and metadata probes. The [baseline summary](../qualification/evidence/standards-corrections/baseline/summary.json) records the original report, CSV and archive hashes and the fixture adaptations. The three independent input files and their recorded outcomes remain unchanged outside the repository.

## Verification gaps and dispositions

H-01 uses the original fixtures plus a standards-derived positive/negative calendar corpus. It checks RRULE structure and BY restrictions, conditional date/duration relationships, parameters, alarm anchors/repeats, attachment representation, numeric/period/date boundaries, CALSCALE, structural case, folded UTF-8 and TEXT interpretation. Split UTF-8 folding is unfolded before strict decoding and encoded faithfully in report XML; GET remains byte exact. A general `validate()` call is not treated as proof of all optional extension grammars. The matrix identifies the clauses exercised and any remaining narrow interpretation limits.

H-02 uses disposable embedded root and prefixed Nginx HTTPS arrangements, configured canonical discovery/issuer routes and hostile forwarded headers. Actual TLS negotiation checks supported1.2/1.3, obsolete versions/key exchanges, trust and hostname identity. Production DNS, operator certificates and network isolation have not been provided and are not falsely reported as verified or defective.

H-03 extends the actual packaged `backup.sh`/`restore.sh` workflow with nine original accepted fixtures, nine rejected controls, immutable history/properties, stable and continuation tokens, representative shares and the corrected future timezone. It verifies old sessions/DAV/OAuth/factors/state cannot revive, fresh recovered access preserves bytes, and revoked READ aliases are denied. No schema change is required by these corrections; existing forward migrations and same-version/V9 upgrade checks remain enabled.

H-04 adds a real password→passkey→consent→code/S256→token/refresh/revoke journey, token-cache and request-boundary controls, signed registration/assertion negatives, persistent verified backup-state changes/restart, and a disposable HTTPS OIDC issuer serving genuine signed ID tokens, discovery, JWKS and UserInfo. Wrong issuer/state/nonce/audience/azp/signature/expiry/algorithm/key and subject mismatch are tested, with legal controls and key rotation. These are not provider mocks. The existing real Keycloak suite and packaged browser profiles remain separate checks. Physical authenticators and optional authenticator extensions remain unverified.

H-05 records URI alias authorization, property/snapshot interleavings and size boundaries. For freebusy, RFC4791 §7.3 specifically requires collection timezone and §9.11 does not define a request-timezone child; RFC4918 §17 therefore ignores that unexpected subtree. Calendar-query retains its defined request timezone. A clean floating-event HTTP control verifies the distinction. PUT body limits retain transport413 and identify CALDAV:max-resource-size where applicable; generic report/sync limits are not globally remapped.

H-06 retains the large-group test enabled and preserves all failed executions. Its original transaction timeout was not an assertion proving a protocol defect. Fresh isolated/full-suite/CI outcomes are recorded with actual counts; production transaction limits and assertions are not weakened to manufacture success. Performance measurement is deferred. The current packaged CI correctness profile uses `--clients`, without the historical capacity/latency workload.

## Preserved decisions and nonblocking recommendations

Java25, Spring Boot4/Security7, PostgreSQL, embedded authentication and optional Keycloak remain. Dependencies and base-image pins, Apache-2.0 delivery and third-party notices are retained. Neither copied upstream parser/timezone source is modified; independently implemented application adapters use supported library APIs. No Digest, primary-password DAV, scheduling, CardDAV, locking, file hosting, non-Gregorian execution or notification feature is added.

The approved default sync Depth1 accommodation applies only to sync-collection with XML sync-level1; missing/Depth0 and explicit strictfalse remain separately verified. HTTPS DAV credentials/Bearer remain the selected authentication profile, with the documented historical Digest deviation. Those decisions are not among the17 implementation defects.

Leap-second fallback remains the explicit narrow SHOULD exception described in [calendar semantics](calendar-semantics.md). Unsupported RSCALE now fails explicitly without adding execution. allprop omits ACL section5 live properties and sync-token per their recommendations, while explicit/include/propname remain available. No-op direct grants and identical ACL replacements preserve sync state; real authorization changes still invalidate principal-dependent continuation snapshots. Authorized conflict-href diagnostics remain optional and are not used to disclose an inaccessible object.

Previously accepted invalid data remains retrievable and repairable; use the documented GET/ETag/conditional-PUT or DELETE procedure, without batch deletion or rewriting. No new migration or database recreation is prescribed.
