# Protocol correction traceability

This record maps previously reported protocol and security findings to their
application corrections and maintained regression tests. It is engineering
traceability, not certification or universal interoperability.

The independent review covered 17 finding groups. Subsequent verification closed
sixteen original groups and identified two residual input-validation obligations:
original BYDAY/duration grammar and exactly empty public-client secrets. Their
regressions are retained in the calendar and OAuth test suites. Historical result
classifications, failed attempts, artifact identities and detailed audit reports
remain in the [evidence archive](../qualification/evidence/README.md#historical-records).
Current executable/client scope is recorded in the version-specific qualification
receipt; final distribution identities come from the release manifest.

## Verification gaps and dispositions

The following paragraphs distinguish completed local verification from remaining scope limits. The manifest records exact commands/counts and preserves failed and superseded attempts.

H-01 uses the original fixtures plus a standards-derived positive/negative calendar corpus. It checks RRULE structure and BY restrictions, conditional date/duration relationships, parameters, alarm anchors/repeats, attachment representation, numeric/period/date boundaries, CALSCALE, structural case, folded UTF-8 and TEXT interpretation. Split UTF-8 folding is unfolded before strict decoding and encoded faithfully in report XML; GET remains byte exact. A general `validate()` call is not treated as proof of all optional extension grammars. The matrix identifies the clauses exercised and remaining broad per-property grammar and specific interpretation limits.

H-02 uses disposable embedded root and prefixed Nginx HTTPS arrangements, configured canonical discovery/issuer routes and hostile forwarded headers. Actual TLS negotiation checks supported 1.2/1.3, obsolete versions/key exchanges, trust and hostname identity. Production DNS, operator certificates and network isolation have not been provided and are not falsely reported as verified or defective.

H-03 extends the actual packaged `backup.sh`/`restore.sh` workflow with nine original accepted fixtures, nine rejected controls, immutable history/properties, stable and continuation tokens, representative shares and the corrected future timezone. It verifies old sessions/DAV/OAuth/factors/state cannot revive, fresh recovered access preserves bytes, and revoked READ aliases are denied. No schema change is required by these corrections; existing forward migrations and same-version/V9 upgrade checks remain enabled.

H-04 adds a real password→passkey→consent→code/S256→token/refresh/revoke journey, token-cache and request-boundary controls, signed registration/assertion negatives, persistent verified backup-state changes/restart, and a disposable HTTPS OIDC issuer serving genuine signed ID tokens, discovery, JWKS and UserInfo. Wrong issuer/state/nonce/audience/azp/signature/expiry/algorithm/key and subject mismatch are tested, with legal controls and key rotation. These are not provider mocks. The existing real Keycloak suite and packaged browser profiles remain separate checks. Fresh H-04 negatives also exposed registration exception translation and malformed token-parameter handling; application integration now returns the intended failure without login redirects, persisted credential changes or lost MFA continuity. These are developer verification discoveries, not newly assigned independent finding IDs. Physical authenticators and optional authenticator extensions remain unverified. The additional-audience trust-policy interpretation in AUTH-R078/R085 is retained separately from the executed issuer/audience/azp negatives.

H-05 records URI alias authorization, property/snapshot interleavings and size boundaries. For freebusy, RFC 4791 §7.3 specifically requires collection timezone and §9.11 does not define a request-timezone child; RFC 4918 §17 therefore ignores that unexpected subtree. Calendar-query retains its defined request timezone. A clean floating-event HTTP control verifies the distinction. For mixed multi-valued parameter negation, RFC 4791§9.7.3 permits text-match in its grammar but omits that case from its prose; §9.7.5 does not place the list quantifier. The current per-value reading has support in RFC 5545§3.2.11’s individual MEMBER values. CAL-R086 retains this precise interpretation gap; no mandatory defect is inferred from the ambiguity. PUT body limits retain transport 413 and identify CALDAV:max-resource-size where applicable; generic report/sync limits are not globally remapped.

H-06 retains the large-group test enabled and preserves all failed executions. Its original transaction timeout was not an assertion proving a protocol defect. Fresh isolated/full-suite/CI outcomes are recorded with actual counts; production transaction limits and assertions are not weakened to manufacture success. No new performance qualification is inferred. The current packaged CI correctness profile uses `--clients`, without the historical capacity/latency workload.

## Preserved decisions and nonblocking recommendations

Java 25, Spring Boot 4/Security 7, PostgreSQL, embedded authentication and optional Keycloak remain. The original correction pass retained dependency and base-image pins, Apache-2.0 delivery and third-party notices. The residual qualification refreshes only the official Temurin base digest for the confirmed OS advisory recorded in the archived packaging evidence; the Java release and Maven dependencies remain pinned. Official iCal4j artifacts remain unmodified; application-owned adapters use supported library APIs. No Digest, primary-password DAV, scheduling, CardDAV, locking, file hosting, non-Gregorian execution or notification feature is added.

The approved default sync Depth: 1 accommodation applies only to sync-collection with XML sync-level=1; missing/Depth: 0 and explicit `allow-sync-depth-one=false` remain separately verified. HTTPS DAV credentials/Bearer remain the selected authentication profile, with the documented historical Digest deviation. Those decisions are not among the 17 implementation defects.

Leap-second fallback remains the explicit narrow SHOULD exception described in [calendar semantics](calendar-semantics.md). Unsupported RSCALE now fails explicitly without adding execution. allprop omits ACL section 5 live properties and sync-token per their recommendations, while explicit/include/propname remain available. No-op direct grants and identical ACL replacements preserve sync state; real authorization changes still invalidate principal-dependent continuation snapshots. Authorized conflict-href diagnostics are deferred as a nonblocking SHOULD recommendation; the precise conflict condition remains available, and an inaccessible conflicting URL is never disclosed.

Previously accepted invalid calendar objects remain retrievable through authorized GET and repairable with ETag/conditional PUT or DELETE. Invalid collection calendar-timezone values are repaired through authorized PROPPATCH. Do not batch-delete or rewrite them. No new migration or database recreation is prescribed.
