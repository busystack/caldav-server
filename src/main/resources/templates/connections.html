Connection troubleshooting

Authentication fails

Check the username and dedicated credential. Issue a replacement if it expired or was lost. Revocation and account disabling deny future authentication. Organization-managed accounts also need periodic provider sign-in within the operator's configured freshness limit; provider disabling does not immediately revoke every BusyStack credential.

Collections are missing or access changed

Check Calendars & Tasks. A collection owner must grant access directly or through a group. Refresh discovery after a change. If a synchronization token becomes invalid after sharing changes, let the client perform a fresh initial synchronization.

TLS, address or synchronization problems

Use exactly the configured HTTPS address, including any application prefix. Do not disable certificate validation. Ask the operator to check certificates and proxy configuration.

Strict synchronization-depth mode is enabled. The project's tested Thunderbird and python-caldav versions use Depth: 1 and need the documented default accommodation; ask the operator to review this deployment choice.

BusyMax has not been qualified against this implementation. No connection or OAuth compatibility claim is made.
